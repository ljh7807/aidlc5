# 주류 예약 O2O 플랫폼 - Requirements

> **문서 상태**: Draft  
> **작성자**: Owner  
> **최종 수정**: 2026-09-29  

## 1. 프로젝트 개요

### 1.1 목적
데일리샷과 유사한 **주류 예약 O2O 플랫폼**의 POC(Proof of Concept) 개발

### 1.2 비즈니스 목표
- 사용자가 원하는 주류를 온라인으로 예약하고 오프라인 가맹점에서 픽업
- 가맹점의 재고를 실시간으로 확인하여 예약 가능 여부 판단
- 성인인증을 통한 주류 판매 규제 준수

### 1.3 기술 스택
| 구분 | 기술 |
|------|------|
| Backend | Node.js, Express, TypeScript, SQLite |
| Frontend | React Native, TypeScript |
| 인증 | JWT |
| 테스트 | Jest |

## 3. 비기능 요구사항 (Non-Functional Requirements)

### NFR1: 성능
- API 응답 시간: 평균 200ms 이내

### NFR2: 보안
- JWT 기반 인증
- 비밀번호 해시화 저장
- 성인인증 필수 (주류 관련 API)

### NFR3: 확장성
- 레이어드 아키텍처 (Routes → Services → Repositories)
- 데이터베이스 추상화 (SQLite → 다른 DB로 교체 가능)

## 4. POC 범위 및 제약사항

### 4.1 POC 범위 내 (In Scope)
- ✅ 기본 CRUD 기능
- ✅ JWT 인증
- ✅ SQLite 데이터베이스
- ✅ 테스트 결제 (Mock)
- ✅ 시드 데이터 (주류 5종, 가맹점 3개)

### 4.2 POC 범위 외 (Out of Scope)
- ❌ 실제 PG사 결제 연동
- ❌ 본인인증 서비스 연동 (PASS 등)
- ❌ 푸시 알림
- ❌ 위치 기반 검색 (GPS)
- ❌ 웹 버전
